Wide keys light across their whole width.

## Why

Four keys on this layout carry two leds each and the map only ever recorded one of
them, so backspace, caps lock, left shift and the super key lit at half their width.
The gap was invisible because the second led sits at an index the map listed as a
hole, and every neighbouring key really is a hole, so nothing looked out of place.

## Changed

- `kbKey` carries an `indices` array and `cmdKbdSetMap` emits every led for a key, so
  one paint covers the whole key. This flows through every write path: manual paints,
  the theme colour, the mute overlay and the restore that runs on resume

| key | indices |
| --- | --- |
| backspace | 34 + 35 |
| caps | 60 + 61 |
| lshift | 80 + 81 |
| lsuper | 102 + 103 |

- The map is now complete: 88 leds across 84 keys. The remaining 48 indices are
  genuine matrix holes. There is no addressable zone for the mute indicators and the
  caps lock dot is not in the matrix either, both are firmware driven
- `npm test` is scoped to `tests/`. Bare `node --test` also walked the clone that
  makepkg leaves in `packaging/`, running a stale copy of the whole suite a second time
- The readme documents the key map, the `kbd identify` verb, the advisory flock, and
  the fact that the PKGBUILD builds a tag rather than the working tree
