Per key keyboard lighting, lighting that survives a suspend, and a working colour wheel.

## Fixed
- Lighting never came back after the laptop slept. `lightsRestored` and `keyboardRestored` were
  one shot latches with no reset path, and `keepLoaded` keeps the service alive across a suspend,
  so the restore never fired again for the life of the shell. A logind `PrepareForSleep` watcher
  re-arms them on the resume edge
- The same two latches were set before the ready and present checks, so a first poll that caught
  the device absent burned the latch permanently and stopped the retry timer
- Restoring keyboard lighting raised a password prompt on resume. polkit was called with user
  interaction allowed, and a locked session is not active, so it challenged instead of declining.
  The `set-keyboard` check is non interactive now, and a denied write re-arms the restore so the
  colours land after unlock
- Thirteen keys lit the wrong lamp. The index table had been inferred from the visual layout
  rather than measured. The four media keys sit at 16 to 19, below the number row, not spliced
  into the middle of it, and the number row is contiguous from 20 to 32. Left shift is 81, not 78
- The colour wheel was mirrored. The hit test and the marker used screen down y while the gradient
  paints hue counter clockwise, so clicking a colour selected its reflection
- Dragging the wheel or the value bar round tripped through an 8 bit hex and reassigned hue and
  saturation on every step. Dragging value to the bottom emitted `000000` and lost the hue
- The wheel hit area was the whole square rather than the painted disc, so a corner click set a
  colour
- The theme colour painted the chassis only and never the keyboard, with theme sync on
- Queued `kbd set-map` writes were dropped by queue coalescing, so painting keys faster than one
  helper round trip lost writes the panel had already committed and saved
- `rgb status` could run while a write was queued, holding `/dev/hidraw0` open alongside the
  writer, which is the documented way to wedge the AW-ELC controller

## Changed
- `kbd identify <idx>` lights one wire index and blanks the rest, so the map can be verified
- `hidraw.Open` takes an advisory `flock`, so the CLI, the daemon and the plugin serialise on a
  node instead of racing. A contended node reports `hidraw-busy` after a bounded wait
- The daemon holds the keyboard device open for its lifetime and reopens only after an error,
  instead of opening and closing on every call
- The two mute keys follow PipeWire, red while muted, as an overlay that is never written into
  the saved colours
- The thermal profile is restored across a suspend from a snapshot taken on the pre sleep edge,
  landing after power-profiles-daemon rather than before it
- `rgb status` reports readiness from a real probe instead of a hardcoded true
- elc discovery tries product id `0550` then `0551`, matching what the udev rule already grants
